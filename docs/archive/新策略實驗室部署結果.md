## 搜尋怎麼改

原始 V5 每次隨機取 1–3 個關鍵字：先取使用次數較低的 count×3 筆，再洗牌選取；將數個關鍵字拼成一個搜尋字串，加上一個隨機通用後綴，只取 5 個結果。找到搜尋結果會增加 used_count，產生每個策略檔時又會增加一次 used_count 與 success_count。success_count 代表產生策略檔成功，並非回測獲利，所以它沒有把搜尋導向樣本外表現好的策略。

新專案只種入 6 個資料相容家族：Donchian 突破、趨勢回調、Bollinger Bands %B、RSI 超買超賣、波動壓縮、ROC 動能。所有計數歸零。每個家族先獲得兩輪搜尋，之後依 2024 驗證期的報酬、PF、Sharpe、回撤及交易數配置搜尋權重，並保留 20% 機率探索使用較少的家族。2025–2026 的評估結果不參與關鍵字選擇。

每輪使用一個家族的 3 個相關查詢，每個查詢最多 8 個搜尋結果。必須取得完整網頁或 GitHub commit 的程式證據；限制每輪最多 3 次模型請求，包含翻譯與後續語意複核，最多產生 2 個候選。若複核所需預算不足，保留來源待後續重試。

修正 supported=false/spec=null 的解析錯誤；允許 period=14 等不可變固定預設值，仍拒絕會執行程式或保存可變狀態的預設值；GitHub README 連結會繼續尋找策略 Python 檔。翻譯完成後另做語意複核，檢查週期是否來自該策略實例、做多/放空方向、持倉條件、出場與指標計算。因果、確定性與方向檢查仍保留。模型複核不能替代最終人工來源核對。

## 第一輪實際結果與問題

第一輪 RSI 搜尋取得 19 個不同候選網址，實際處理 10 個，9 個拒絕、1 個最初產生程式，使用 3 次模型請求。v1 來源為 https://github.com/joseporiolcarne/backtraderalerts 。

人工核對 commit `20c45d2c8bbdb6fb4452ca17dc78667ac6bc343d` 的 `src/strategies/rsi_crossover.py`，發現原始程式在空倉時買入、持有多單時賣出；翻譯卻增加放空及反向出場。4h 只來自框架的支援週期清單，未證實是該策略的指定設定。因此 v1 保留全部紀錄並改為 source_review_failed / review_status=rejected，qualified=false，不納入搜尋績效回饋。這次發現促成上述翻譯後語意複核；後續候選必須通過該步驟才能回測。

v1 已完成的歷史計算為：2025 起 BTC 報酬 -10.0352%、最大回撤 19.3435%、PF 0.6869、24 筆交易。因來源翻譯錯誤，這些數字只能作為問題追蹤，不能代表原策略的忠實回測表現。目前沒有新實驗室核准的策略。
