## 2. 正確的過去位移被當成偷看未來：P0

`backtest_engine.py:477–478` 拒絕 `np.concatenate(([...], arr[:-N]))`，並稱為 lookahead。以 N=1 而言，這是將過去資料延後：`[1,2,3] → [0,1,2]`，並非使用未來。

搜尋程式 `strategy_hunt.py:109` 明確要求這種寫法；回測卻拒絕它，兩端契約互相矛盾。4,259 支策略中 3,482 支包含此規則所匹配的模式（約 81.8%）；這是「可能被目前規則拒絕」的靜態暴露範圍，不是 3,482 支已證實遭誤殺。

原始日誌 `pytest/logs/last_run_20261008_115724.log` 確認 v3624 因此被移走。`Strategy_fail/3624_Strategy_Gold.py` 的 Heikin-Ashi 計算使用過去遞迴與上述正向位移；本次抽查的程式沒有發現該位移構成未來洩漏。這不代表該策略一定有收益。

記憶 `pytest/memory/2026-10-07.md` 與 10-05 紀錄沿用「shift(+N) 是 lookahead」並建議 translator 避免，錯誤認知持續累積。

解法：移除錯誤規則，使用 AST 分析加因果性測試；修正相關記憶／SOP，避免 agent 再沿用誤判。重測被此原因攔截的策略，但不要直接提升為 Good。

其他 regex 也過度嚴格：未 shift 的累積函式不自動等於看未來；是否合規取決於決策及成交時點。變數切片也不能一概視為 leak。

## 3. 時間對齊重複延遲：P0

搜尋要求指標 shift(1)；回測 `:389–391` 再取 `ls[i-1]`，`ATR` 在 `:260` shift(1) 後，進場又用 `atrs[i-1]`。對遵守 prompt 的策略，開盤 i 的決策可能依賴 i-2 的已收盤資料，較「i-1 收盤判斷、i 開盤成交」多延遲一根。

如 v3623 的訊號已經比較 cmo.shift(1) 與 shift(2)，回測再延遲。延遲會改變策略，影響方向不能一概判定。

解法：訂一個時點契約。建議 signal[t] 代表 t 收盤後決策，引擎統一在 t+1 開盤成交；ATR 也由同一契約取值。禁止模型與引擎各自盲目位移；用已知事件的合成資料確認進場 bar。

## 4. 成交模擬與績效指標：P0/P1

`run_simulation` 的問題：

- `:343–406` 使用 if in_position / else，開盤進場後當根不檢查停損停利。合成測試：bar 2 開盤 100，低點 90，停損 99，之後價格 100；引擎回報 0 筆交易，漏掉當根停損。
- 期末未結算持倉；只計已實現損益，沒有持倉浮動 equity。
- drawdown 僅在平倉時更新，忽略期間浮虧，可能低估最大回撤。
- gap 穿越停損仍按停損價處理，未依開盤可成交價處理。
- 同根碰 SL/TP 用固定 seed 的 50/50 隨機，這只是任意假設，並非真實先後順序。
- `:411` 用每筆損益／初始資金的平均與標準差乘 sqrt(交易數)，不是固定時間、年化的投資組合 Sharpe；不同頻率、交易數與持倉時間不能直接比較。
- 未計永續資金費率；若市場是永續合約，需補入真實 funding 資料。其他市場則依對應成本模型。

解法：逐筆 ledger 記錄訊號、成交、費用、倉位及 exit reason；每 bar mark-to-market equity；進場當根處理 SL/TP；gap 採可成交價；有低週期資料時判定碰觸順序，沒有時回報悲觀／樂觀界限；期末平倉或明列浮動損益；日／小時 equity 報酬計算年化績效。

## 5. 統一出場規則改變原策略：P1

translator 只輸出 long/short 布林，不保留原始出場、持有時間、反向訊號、移動停損、部位或多資產配置。引擎所有策略都使用對稱 ATR 停損／停利（1:1），4 個週期 × 7 ATR 搜尋，再以 edge triggering 進場。持倉期間不處理反向訊號；出場當根不重新進場。

結果實際衡量的是「某個訊號 + 自訂出場規則」，未必是原文策略。配對交易、grid、跨資產或需逐筆狀態的策略不能直接塞進单資產 ls/ss。這些策略應標 unsupported，而不是擅自簡化。

解法：建立策略規格（市場、原生週期、entry、exit、position sizing、所需資料），完整保留規則；訊號研究與完整策略研究分開。先在原生週期重現來源，再研究其他週期。

## 9. 篩選不代表策略可靠：P1

`backtest_engine.py:651` 只要 28 組有一組累積報酬 >15% 就 Good。没有年化報酬、最大回撤上限、最少交易數、樣本外、rolling walk-forward、跨行情、參數穩定性或多重測試修正。只選歷史最大值是選擇偏誤。

日志統計（非獨立策略樣本）：346 份；32 份包含錯誤的正向位移 leak 規則，97 份出現恢復時檔案已移走，86 份有載入失敗，141 份有 ATR 矩陣執行，12 份有「通過審判」。項目可重疊且版本可能重測，不能算真實策略通過率。

共解析 3,941 條矩陣報酬：192 條正報酬、53 條 >15%，範圍 -100% 到 427.53%。高報酬同樣需重驗，不是可交易結論。

例 v3456：5m ATR1.5 共 80,550 筆交易、報酬 -100%；1h ATR4.5 共 623 筆、-66.4%。這顯示頻率與成本很重要，但不能單靠此例認定全部問題來自成本。

費用設定 `TRADING_FEE=0.001` 註解寫 round-trip 0.1%，實際 `*2` 是往返 0.2%；加滑價與點差約往返名目本金 0.32%。每次名目部位=資金10%×3，即資金30%，所以一次往返成本約資金0.096%，不是資金0.32%。需依實際交易所、費率等級、maker/taker、商品及成交情況校準，不能為提高績效任意降低成本。

解法：歷史開發／驗證／封存測試分開；開發期選參數，樣本外只評估；固定時間報酬與成本後績效，多年份穩定、回撤、交易量、持有時間、成本壓力、參數鄰域；記錄所有嘗試，採用 Deflated Sharpe 等方法處理大量試驗偏誤。最終用模擬盤驗證成交，不保證實盤收益。

研究依據：[Deflated Sharpe Ratio](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551)、[Optimal Trading with Linear Costs](https://arxiv.org/abs/1203.5957)。

6. 再批次重驗，保留每個原因與所有矩陣結果。依樣本外風險收益晉升，並用模擬盤驗證。
7. 更新 OpenClaw 記憶、cron SOP 與結果通知；「程式正常退出」「有新候選」「真的完成回測」「品質達標」分開報告。
